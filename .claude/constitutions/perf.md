# 性能宪法（DRAFT v0）

> Claude 从仓库现状反推的偏好初稿，**待作者定稿**。
> 性能 Agent 调用确定性工具（图片体积扫描、`compress_image.py`、将来的 Lighthouse），
> 在工具结果之上解读与排序，对照本文件给优先级化的优化建议。

## 图片（最大的体积来源）
- 正文配图优先 **webp**；源图（png/jpg）若已有最新 webp 兄弟，应改引用而非两份都上线。
- 质量 85（`compress_image.py` 默认）是体积/画质的平衡点，无特殊需要不必更高。
- 单图体积关注阈值 **1MB**（`checks.py` 的 `IMAGE_MAX_BYTES`，warning）；超大图优先压缩或限宽。
- 正文图无需超高分辨率；可考虑 `--max-width`（如 1600）限宽。
- 权衡偏好：在"肉眼看不出差别"的前提下尽量小；不为极致体积牺牲明显画质。

## 脚本 / 第三方
- 站点是纯静态 Hugo，**不轻易引入重型 JS 插件**；交互功能（评论/统计）已用 Giscus + Cloudflare，够用即可。
- 任何新增第三方资源都要问：是否阻塞渲染？能否延迟/异步加载？

## 字体（已知优化点）
- 现状：`head-additions.html` 通过 `fonts.googleapis.com` **同步 `<link>`** 加载 Source Serif Pro，属渲染阻塞 + 第三方依赖，Lighthouse 大概率扣分。
- 倾向：后续优化为 `preload` 或自托管子集化字体；但**正文可读性（衬线阅读体验）优先**，不为分数牺牲它。
- 这是"待跑 Lighthouse 后再定"的优化项，不是现在的硬伤。

## Lighthouse
- 先出基线报告、**不设硬阈值**（跑稳两周看真实分布再定）。
- Agent 解读报告时要定位"真正拖分的少数项"并排优先级，而不是罗列所有审计条目。

## 不要做
- 不为分数引入复杂构建链；保持静态站的简单与可维护。
