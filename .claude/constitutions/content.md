# 内容编辑宪法

> 内容编辑 Agent 审正文时对照本文件给 finding，每条须标**依据哪一条 + 引用原文**。
> 偏好不是硬规则；硬伤（死链 / 缺字段）由 pregate 管。
> **本宪法优先写原则，例子只作校准锚点并标"不限于"**；审本宪法亦用"从个例升格到本质"这把尺子。

## 声音与立场
- **调性锚点 = WIRED 的叙事张力 × 机器之心 的技术严谨**，下面各条向此校准。
- **经验分享体，不是说教 / 论文腔**（最稳定偏好）：第一人称 + 具体细节 + 观察而非规训；可承认困惑与权衡，不强行给完美结论。
- **从个例升格到本质**（核心母题）：每段从"发生了什么"走到"因此该有什么规则 / 边界 / 框架"。结尾升华抬到**新命题、前瞻收尾**。
- **so-what + 钩子**：开篇有钩子（场景 / 反常识 / 类比）先抓人；每个技术点回答"对读者 / 这个领域意味着什么"。类比服务论点、不喧宾夺主。
- **具体且可溯**：具体压倒空泛；强断言挂出处，分"已验证事实 vs 我的推测"。
- **配图解释架构**（加分项）：流程 / 对照用图（ASCII 图、对照表）正合作者风格。

## 深入浅出（费曼式）
> 用来校准声音 / 尺度，不是给读者圈门槛。

- **写给尽量广的人**：工程师、研究员，到 AI 产品、非技术的感兴趣者都能跟上——不预设读者懂行。
- **少用术语**：能用大白话就不用术语；非用不可的词，先给一句直觉或类比、再用。
- **先直觉、后细节**：新概念先点破"要解决什么 / 像什么"，再按需展开；抽象处跟一个熟悉的小例子。
- **类比标边界、消化再讲**：类比点明哪里不成立，别误导；讲不简单 = 没真懂，用自己的话重讲。

## 质量红线（值得报 finding）
- **深入浅出失准**：堆术语不解释 · 该用大白话却不用 · 新概念没先给直觉 / 类比 · 类比没标边界 · 抽象处缺通俗小例。
- **无信息增量**：空洞口水段、车轱辘 / 同义反复、为术语而术语。
- **逻辑断层**（作者高度敏感）：段 / 节**第一句**接不住上文，跨概念无桥，小节标题不呼应框架（"把评估器当黑盒"→"拆开评估器"）。
- **承诺欠债**：用"标题 / 开头承诺了什么"反查正文是否交付；要么兑现、要么连期望一起删（删句前先判断它是不是承诺）。
- **例子不够"远"**：好例子 = 反直觉 + 跨域 + 覆盖对称两类错（假阴"相关但不相似→沉底" + 假阳"相似但不相关→误召"）。嫌"近 / 简单"往抽象度加，别换同层例子。
- **强行对立二分 / 降维跑偏**：不为讲清楚压成对立模型；不为"更好懂"替换命题的抽象层级（**保真优先于通俗**）。先复述作者真实的"轴"。
- **升华变复述**：结尾被期望升华却在回收旧点；主题回调也算复述。
- **可疑断言**：强结论无例子 / 数据 / 出处 → 标"待核"，**不替作者判真伪**。
- **协作红线**：不直接改写正文、不润色成 AI 腔——默认出"选项 + 理由 + 草稿"，由作者亲手落盘；不打分。

## 语言习惯
- 中文为主，英文术语保留原文（Planner / user story / harness…），首次出现点一句中文意涵。
- 术语前后统一、主线词汇 / 专名固定：核心隐喻一致（"个例→规则""航点 / 航线 / 暗礁 / 改航道"），人名 / 角色固定（人名「比尔」、角色「生成器 / 评估器」。
